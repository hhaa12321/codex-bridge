# LOCAL-20261105-001: Fix mobile model picker not responding to touch

Status: closed

## Body

## Background / Problem
On mobile widths, tapping the model picker trigger does not open the model picker. The mobile-only rule `html[lang] .composer:focus-within > .composer-status:not([hidden]) { display: none; }` hides the trigger's ancestor when the trigger receives focus during touch activation, so the browser cancels the click. A 390px mobile Chrome/CDP reproduction showed `pointerdown`/`pointerup` followed by `focusin` on `#modelPickerBtn`, then the click targeted `MAIN` and the picker stayed hidden.

## Goal
Make the model picker open reliably on touch-sized mobile viewports while preserving the mobile behavior that collapses the composer status when the text composer has focus.

## Acceptance Criteria
- [ ] Tapping the visible model picker trigger on a mobile viewport opens `#modelPicker`.
- [ ] The composer status remains visible while the model trigger itself is focused.
- [ ] The status still collapses for textarea/composer-shell focus on mobile.
- [ ] A focused regression test protects the selector behavior.

## Planned Validation
- Reproduce and verify with headless Chrome mobile touch emulation before and after the fix.
- Run `npm --prefix web-ui run test:demo-wasm`.
- Run the required demo WASM rebuild, demo test, Vite production build, and workspace tests if applicable.

## Risks / Boundaries
- Keep the fix scoped to mobile composer status focus behavior.
- Do not add compatibility layers or unrelated picker changes.

## Delivery Evidence

### What changed
- Scoped the mobile composer-status collapse rule to `.composer-shell:focus-within` instead of any focus inside `.composer` in `web-ui/src/styles.css`.
- Added regression assertions in `web-ui/tests/demo-wasm.test.js` for the scoped selector and removal of the broad selector.
- Rebuilt the tracked Vite assets under `web-ui/dist` so the embedded daemon UI receives the fix.

### Why this approach
- Touch activation focuses `#modelPickerBtn` before the click completes. The old broad `:focus-within` rule hid the button's `.composer-status` ancestor during that sequence, causing Chrome to dispatch the click to `MAIN` instead of the button.
- Scoping the rule to focus inside the text composer preserves the existing mobile behavior of collapsing status while typing without hiding the model trigger as it receives focus.
